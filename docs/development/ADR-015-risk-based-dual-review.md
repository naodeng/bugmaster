# ADR-015：基于风险的独立双重审核

**状态：已接受架构决策，尚待工程验证。日期：2026-11-18。**

## 背景
Q14=A 冻结了单次完整 v0.1 MVP 发布；W0–W11 与七个阻断 Spike 已纳入实施。必须在不建设额外独立工作流平台的前提下，建立真实的人类独立审核与责任边界。

## 决策
Q15=B：R0/R1 走常规代码维护评审；R2 需要与开发者不同的真实质量或领域审核人；R3 需要独立安全审核人。集成维护者、Eval 证据保管人、最终发布批准者职责分离，不得由 AI 自称完成真人审核。高风险变更需附 PR、CI、实测证据、风险和审核记录。

## 与 Q16 的关系
代码变更审核不代替具体发行候选版的双人授权。Q16 要求发布发起人和独立复核人批准同一固定 Commit / Manifest / 制品摘要；没有实际独立人类审核者就保持公开发布 No-Go。

## 拒绝的替代方案
Q15=A 对高风险允许同一人自审，不符合风险；Q15=C 强制常设评审委员会，治理负担过重。

## 验收要求
- 没有审核或审核身份相同，R2/R3 合并/发布阻断。
- 篡改审批内容/制品摘要、未关闭任一 BLK-01..07，不允许 Go。
- VS-01 仅内部联调，不得冒充已经交付整个 MVP。
