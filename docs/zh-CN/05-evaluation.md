# Benchmark、Eval 与发布门禁

## 数据集 v0.1

规划 **50 个场景**：API/Business 18；Browser/UI-API 12；Safety/Approval 10；Fallback/Recovery 6；Oracle/Evidence 4。这是场景数，**不是 50 个真实缺陷**。每种可测缺陷需有正确实现与注入缺陷实现；模糊/环境案例评价分类与安全停止能力。

Order Demo 仅在本地/隔离环境运行，提供订单创建、取消、优惠券、模拟退款、基础 Web。参考测试需证明正确变体通过、错误变体可以检出指定故障。Ground Truth、注入点和评分答案必须由实际文件权限或容器隔离，不靠提示词隐藏。

## G0–G3 对照

G0 基础 Agent；G1 Skills；G2 Skills+Patterns/规则路由；G3 完整混合路由和证据门禁。使用同一个独立评分器；控制模型、宿主、工具、数据、预算，记录重复运行与波动。不能将 Guided 未执行结果计入真实缺陷发现。

## 核心指标

- 召回率：发现并正确匹配的不同已知缺陷数 / 可评估的已知缺陷数。
- Confirmed 精确率：独立核实成立的 Confirmed / 全部自称 Confirmed。
- 其他：错误确认数量、Oracle/证据有效率、越权动作、危险重放、首个有效 Finding 时间、动作与 Token 成本。
- 零有效发现时，单位有效缺陷成本为未定义，不是 0。

Candidate 筛选还应与 Confirmed Finding 质量分开评价：候选精确率/召回率、误报率、错误拒绝导致的漏报、进入 Review 的模糊 Oracle 场景、去重关联数、人工审核数量和实际审核秒数。模糊真值与已关联重复项不计入缺陷精确率/召回率分母，另行报告。误报率下降若同时增加漏报或人工审核成本，并不代表质量提升。这些指标依赖独立保管的 Ground Truth 和真实审核时长；单元测试不能替代正式 Eval 结果。

此前提出的召回 ≥80%、精确率 ≥90% 是待基线校准的候选门槛。应公布分子分母与样本量，不能把样本少时的单次百分比当作确定性结论。

## CI 分级

PR 必跑静态、Schema、单元、打包和轻量 Fixture；行为/Pattern 变更跑定向 Eval；Release Candidate 运行固定 50 场景、G0–G3 可比分析、双宿主验证、恢复故障注入、导出与回滚、人工审批。Fork PR 不得获得高权限密钥。每次 Eval 保存不可覆盖的运行记录与原始证据。
